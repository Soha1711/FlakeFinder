## Code Under Test — [`regression.py`](demo-repo/src/regression.py)

### [`calculate_total(items)`](demo-repo/src/regression.py:5)

**What it does:**
1. Sums all items in the list.
2. **Regression bug:** Conditionally adds `1` to the total with 50% probability via `random`:
   - If env var `FLAKE_DEMO_SEED` is set → seeds a `random.Random` with that integer, then rolls `rng.random() < 0.5`.
   - If env var is not set → uses the global `random.random() < 0.5`.
3. Returns the (potentially off-by-one) total.

**Flakiness pattern — RANDOM (non-deterministic output):**
- The function has no stable, deterministic return value.
- For any given input, it returns either `sum(items)` or `sum(items) + 1`, chosen at random on each call.
- This is a textbook **random-value flaky test** pattern.

## Tests

### [`test_d_regression.py`](demo-repo/tests/test_d_regression.py) — **Flaky test**
```python
def test_calculate_total():
    assert calculate_total([10, 20, 30]) == 60
```
- Asserts a fixed value (`60`), but `calculate_total` returns `60` or `61` at random.
- This test **fails ~50% of the time** — a classic flaky failure.

### [`test_regression_stable.py`](demo-repo/tests/test_regression_stable.py) — **Stable tests**
All four tests use `in (n, n+1)` assertions, explicitly accepting both possible return values:
```python
assert calculate_total([10, 20, 30]) in (60, 61)
```
- These are written to be **flakiness-aware** and will always pass regardless of the random branch taken.
